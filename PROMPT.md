# PROMPT

## Роль

Ты работаешь как ИИ-агент внутри учебного проекта.

Твоя задача — собрать цельную одностраничную рекламную веб-страницу из материалов, которые заранее подготовлены студентом.

Не заменяй решения проекта универсальным современным шаблоном.

## Перед сборкой

Перед созданием `index.html`:

1. Прочитай `README.md`.
2. Полностью прочитай `research.md`.
3. Полностью прочитай `era.md`.
4. Полностью прочитай `concept.md`.
5. Полностью прочитай `sources.md`.
6. Найди все файлы в `blocks/`.
7. Прочитай файлы `blocks/` в порядке числовых префиксов.
8. Просмотри доступные материалы в `assets/`.
9. Кратко сформулируй для себя:

   * какой объект исследуется;
   * какую эпоху представляет проект;
   * кому адресованы курсы;
   * что они обещают;
   * какие блоки входят в страницу;
   * какие визуальные правила обязательны.

После этого переходи к сборке.

## Источники истины

### research.md

`research.md` является источником исторических фактов.

Не меняй даты, имена, события и исторические связи без основания в этом файле.

### era.md

`era.md` является источником решений о времени и визуальной среде.

Он определяет:

* период;
* технологическую среду;
* визуальный язык;
* типографику;
* цвет;
* плотность;
* рамки;
* кнопки;
* характер изображений;
* допустимые и недопустимые современные элементы.

### concept.md

`concept.md` является источником рекламной идеи.

Он определяет:

* название курсов;
* аудиторию;
* главное обещание;
* голос;
* центральную шутку;
* основной смысл страницы.

### blocks/*.md

Файлы в `blocks/` определяют структуру страницы.

Сохраняй порядок числовых префиксов.

Не добавляй новые смысловые секции только потому, что современные лендинги обычно содержат дополнительные блоки.

### sources.md

`sources.md` содержит подтверждения исторических фактов и визуальные ориентиры.

Используй визуальные решения, которые можно связать с указанными источниками.

### assets/

Используй локальные материалы из `assets/`, если они доступны.

Подключай изображения только относительными путями.

## Главная задача

Создай `index.html`.

Страница должна рекламировать вымышленные курсы по JavaScript так, как это могло бы выглядеть в выбранную эпоху 1995–1997 годов.

На странице должны считываться:

* историческая роль JavaScript;
* браузер как программная платформа;
* интерактивность;
* адресат курсов;
* характер раннего коммерческого веба.

## Содержание

Используй `blocks/*.md` как структуру страницы.

Сохраняй порядок блоков.

Можно улучшать формулировки ради читаемости, ритма и цельности.

Нельзя менять смысл проверенных исторических фактов.

Не придумывай:

* даты;
* цитаты;
* рейтинги;
* известных пользователей;
* несуществующие исторические события;
* статистику;
* отзывы;
* награды.

Если необходимый факт отсутствует, используй нейтральную формулировку или сообщи о пробеле.

## Визуальная система

Опирайся на `era.md` и визуальные источники.

Страница должна выглядеть как работа, связанная с 1995–1997 годами.

Используй:

* простую типографику;
* плотную композицию;
* прямоугольные блоки;
* тонкие рамки;
* текстовые ссылки;
* простые кнопки;
* небольшие изображения;
* техническую графику;
* ограниченную цветовую палитру.

Не превращай страницу в современный SaaS-лендинг.

Не используй без исторического основания:

* большие скруглённые карточки;
* glassmorphism;
* современные градиенты;
* огромные пустые hero-блоки;
* современные сетки преимуществ;
* современные UI-компоненты;
* смартфоны;
* современные социальные сети;
* современные DevTools;
* современные фреймворки как часть исторической среды.

## Юмор

Юмор должен исходить из исторического контекста.

Основная идея:

**браузер уже умеет показывать страницы — теперь его можно научить выполнять поручения.**

Не добавляй случайные шутки о 1990-х, если они не связаны с историей JavaScript или выбранной эпохой.

## Технический результат

Основной файл:

`index.html`

Страница должна открываться локально без установки отдельного сервера.

CSS можно разместить внутри `index.html`.

JavaScript используй только там, где он нужен для концепции страницы.

Внешние библиотеки и сетевые зависимости для просмотра страницы не требуются.

Изображения подключай относительными путями, например:

`assets/images/example.png`

Никогда не используй пути вида:

`C:\Users\...`

или другие абсолютные пути компьютера студента.

## Проверка перед завершением

Перед завершением проверь:

1. Все блоки из `blocks/` представлены на странице.
2. Порядок блоков сохранён.
3. Исторические факты соответствуют `research.md`.
4. Визуальные решения соответствуют `era.md`.
5. Рекламная идея соответствует `concept.md`.
6. Нет придуманных исторических фактов.
7. Страница читается на обычном экране ноутбука.
8. Изображения используют относительные пути.
9. Ничего важного не перекрывается.
10. Страница выглядит как единая исторически обоснованная работа.

## Главное правило

Если современный дизайн и историческая точность конфликтуют, выбирай историческую точность.

Если визуальный эффект не подтверждён `era.md` или `sources.md`, не добавляй его без необходимости.

Если решение уже записано в Markdown-файлах проекта, не заменяй его собственным вариантом.
